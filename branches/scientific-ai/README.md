# Scientific AI and retained evidence

This branch asks what an AI system must retain so a later answer or action still has its warrant. Its record includes source bytes, versions, dependencies, checks and authorized operations.

The connection to The Bounded Observer is operational sufficiency: forgetting is acceptable only relative to the future tasks the retained record must support. A citation, a proof, a dataset result and an authorization are different record types.

- Engineering contributions to upstream systems, with their own code and review histories.

## Operational contract

Records are typed evidence and task state. Readings are allowed conclusions or actions. Updates include source changes, queries, checking and dependency invalidation. Composition follows the specified verification rules. The retained state preserves consequential dependencies and current warrant while keeping failed history.

There is no necessary physical probability normalizer. The relevant time is event/version ordering and the stated warrant policy. A source's age alone does not determine whether it remains valid.

Prototype checks establish their finite implementation behavior. Active Context's first diagnostic tied conventional invalidation; it did not establish a performance advantage. A new efficiency or correctness claim needs a fixed comparative workload and loss condition.
